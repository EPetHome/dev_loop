# dev-loop

开发卡授权范围内，推进「开发 → 收货 → 复测 → 独立评审 → 返修或完成」。每次读一份只追加账本，补缺的那一步。调度不调用模型；合入、部署各自核对放行证据。没验证不算通过，技术结论不等于本人验收。

## 快速开始

要求 Node ≥22.19、Git（支持 `merge-tree --write-tree`）、macOS Terminal 和 Pi。Linux 可用 `flock` 跑非窗口工具和测试。不装 npm 依赖。示例中的 `bin/loop` 在其他项目中用绝对路径。

```json
{
  "version": 1, "name": "小改动", "nature": "开发", "target": "dev",
  "flow": ["开发评审", "测试"],
  "tasks": [{"name": "甲", "prompt": "提示词.md", "scope": ["src/**", "test/**"], "test": "node --test test/*.test.ts"}]
}
```

```sh
bin/loop 安装定时                       # 在使用新版的机器上安装一次，测试时不用
bin/loop 启动 docs/batches/小改动/开发卡.json
bin/loop 交付 --说明 '改动和自测'        # 在登记的开发工作区中
bin/loop 查询 --all --brief --json
```

工具或 Pi 插件记完事实即叫醒调度；`bin/loop 安装定时` 在当前用户的 LaunchAgents 安装兜底，按仓库 `config/defaults.json` 的 `tickIntervalSec` 执行 `tick --all`。改间隔或迁移安装路径后重新安装；`bin/loop 卸载定时` 停用并删除该项。没有真实安装权限、或不是 macOS 时，可由现有定时任务运行同一个 `bin/loop tick --all`，也可手工单次运行。切换前先停旧执行；旧执行只可查询，不由新版推进。

## 命令

| 命令 | 作用 |
|---|---|
| `启动 <卡> [--派单编号 X] [--指令编号 Y]` | 保留 PA 同步回执；开工后后台准备。重复投递返回原执行号 |
| `开工 <卡…> [--依赖 后项=前项] [--话 原话]` | 同一批可传多个卡文件；依赖可重复，项用卡名、路径或从 1 开始的序号 |
| `查询 [<卡或执行编号>\|--all] [--brief] [--json]` | 现算阶段、放行证据异常、规则命中、等待说明和恢复汇总 |
| `tick [--all]` | 每卡补一步，后台工具接力；没有任务目录参数时扫运行目录 |
| `交付 [--说明 文本\|--text-file 文件] [--截图 文件…]` | 开发工作区收货：范围检查后提交、登记；不在这个命令里跑复测评审 |
| `提问 <原话>` | 开发登记疑问，不写意图，也不放行 |
| `答复 <卡或执行编号> (--话 文本\|--text-file 文件)` | 本人原话；关闭疑问或解除本人中止 |
| `续跑 <卡或执行编号> [--话 文本\|--text-file 文件]` | 轮数用完加一轮；带话答复；环境或收尾失败时立即重试；停止后可继续 |
| `加轮 <执行编号> <轮数> [--话 原话]` | 按当前耗尽步骤加轮；已有必修不消失，仍须新交付 |
| `停止\|放弃 <执行编号> [--话 原话]` | 停止保留工作区；放弃移除工作区，保留分支与证据 |
| `准备\|开窗口\|复测\|评审 <执行编号> [--commit sha]` | 单步工具；复测、评审仅对登记的收货提交；不替本人增加轮数 |
| `合入 <执行编号或卡路径> [--commit sha] [--接受未验证] [--话 原话] [--推送]` | 本地 dev；显式接受未验证写版本绑定的本人意图；默认不推送 |
| `部署 <执行编号或卡路径> [--commit sha]` | 部署最后收货版本，独立核证，不默认取 dev 上其他版本 |
| `推送\|释放\|退回\|陪跑 <执行编号>` | 推送已合入版本（只到 origin/dev）、清理干净工作区、回退最新部署、采基线 |
| `对比 <执行编号> [<另一个执行编号>]` | 对比部署快照，只报告差异 |
| `证明 <执行编号>` | 两版隔离跑旧红新绿，只提供防复发证据，不参与放行 |
| `安装定时\|卸载定时` | 管理 macOS 当前用户的 launchd 兜底定时项 |
| `帮助` | 打印命令表 |

成功输出 JSON（`--json` 单行），拒绝/错误 stderr 为 `{error:{category,raw,result?}}`、退出码 1。支持 `--task 名` 核对任务名；有多个活动执行时指定执行号。`LOOP_TASKS_ROOT` 可换执行根目录；开发窗口用 `LOOP_TASK_DIR` 定位。开发入口不接收本人意图或执行附加工具。

## 开发卡

卡文件引用相对卡目录，`scope` 相对仓库根。`version: 1`、`nature: "开发"`、`name` 必填；`target` 固定 `dev`，`base` 默认 `dev`（须为已有本地分支，不可为 `main`），`host` 只支持 `pi`。`flow` 以 `开发评审` 开头，按 `开发评审, 测试, 合入, 部署, 推送` 顺序选用；部署、推送须含合入。没有收尾授权就只做检查。批次替代 `next`，每个卡文件仍一个任务。依赖在写任何账本前核对，被依赖的卡必须授权合入；下张卡准备时才取分支起点。

- `tasks[].name`、`prompt`（仓库内文本，≤200 KB）、`scope`（数组或 `{ "allow": [...], "deny": [...] }`，支持目录、`*`、`**`、`?`）。
- `tasks[].test`：项目测试命令；没有可跑的写 `无：原因`，结论显示「没验证」，不满足普通放行。
- `acceptance`：可选验收标准文件，绑定结论。`limits`：覆盖 `测试 / 开发评审 / 部署` 各自的 `maxRepairs`、`timeoutMin`。
- `tasks[].版式`：如 `{ "草图": "页面草图.md", "页面": ["首页", "结果页"] }`。交付附 `首页.png`、`结果页.png` 等截图；页面可写完整截图名。不齐不收货，只发回补图，不扣轮。评审读草图及图像。
- `tasks[].e2e`：场景 `id`、`checks`、可选 `paths`、`dependencies`。从收货版本和 dev 的合并基点选跑（含删除、改名两端）；没设路径则每次跑。`checks` 为名字或 `{ "id": "完成通知数", "expected": 1 }`。[项目报告格式](docs/参考-运行细节.md#e2e-项目报告)。
- `tasks[].proofs`：防复发证明，登记 `issue`、`testFiles`、`test`、`beforeActual`、`expected`、一个 `testName` 或 `scenario` / `checkpoint`。`before` 默认准备时起点，可填本地旧提交。`proofTestDirs` 在项目配置登记。[证明报告](docs/参考-运行细节.md#防复发证明报告)。

## 配置

`config/defaults.json` → 项目 `.autoreview.json` → 开发卡 `limits`。开工合并固定；机器的 `tickIntervalSec` 除外。要给执行用新配置，请用新的开工输入；旧执行仍用原配置。

- 默认开发 `gpt-6.2-sol/max`、评审 `gpt-6-astra/xhigh`、分诊 `gpt-6.2-sol/xhigh`（完整模型名见默认文件）。`retry` 默认 3 次、`delaysMin: [1,4,16]`，`cardRetryBudget: 10`；`newSessionAtContext: 0.5`；同批 `maxParallelCards: 1`；`notifyAutoSummary: true` 控制自动处理摘要。默认测试/评审/部署返修上限为 3/4/2，时限为 20/60/20 分钟。
- `setup` 环境准备命令、`localFiles` 仓库相对路径清单；原样复制不算越界。`reviewerCmd` 为空用新开只读 Pi；覆盖时是仓库相对可执行评审脚本（参数：轮次、输入路径、会话编号）。
- `snapshot`、`deploy.cmd/check/rollback` 为仓库相对可执行脚本；自动部署须三个均登记。`deploy.env` 为大写环境变量，不用 `LOOP_` 前缀，不写密钥。部署和推送不碰 main、不强推、不 stash/reset 用户改动。
- 项目 `REVIEW.md` 和其中的相对链接从起点提交读取；仅凭截图验的条目不报静态必修。[项目评审规则](docs/参考-运行细节.md#项目评审规则)。开发窗口可显式加载[项目验证手册](docs/参考-运行细节.md#pi-开发验证手册)，不替代复测。

## 等本人和证据

| 什么时候 | 如何继续 |
|---|---|
| 需求疑问（含阻断评审疑问） | 答复原话或停止；对疑问直接在窗口回话也算答复 |
| 轮数用完 | 收窄、加轮、显式接受未验证或停；查询给出剩余必修及收敛趋势 |
| 开发推不动 | 答复给方向或停止；含反复冲突，冲突不扣检查轮 |
| 环境修不好 | 修好以后续跑、或停止；重试耗尽才通知，回退失败例外 |
| 本人在 Pi 按 Esc | 不重开、不推通知；本人在窗口再说话或 `答复 --话 继续` 才解除 |

忘了交付先提醒一次；仍没交付才分诊。只有正常停下可能自动收货，网络错按退避发继续；断线优先重开原会话。

`~/.dev-loop/tasks/<执行编号>/ledger.jsonl` 是新版唯一推进依据。`status.json` / `checks.jsonl` 为 PA、历史工具用投影，丢失后从账本重写。`task.json`、`summary.md`、正式答复、窗口原话、复测和评审原稿、截图、部署证据均在执行目录。不直接发送飞书；PA 保持旧接口。

## 协调工具：开工复盘、收单和体检

开工前可用 `node tools/coordinate.ts 开工 --project <项目目录> --card <待开工卡>` 预览上一批信号、重复候选、关单证据和体检。`查询`、`体检`、`月报 --month YYYY-MM`、`候选决定 --decision <文件>` 同样指定项目。默认只读；经批准才在原参数后加 `--apply <planId>`。不改 PA，不代投递或上线。[输入及归档格式](docs/参考-运行细节.md#协调工具的输入和存档)。

## 自检

```sh
node --test test/*.test.ts
bash -n bin/loop bin/pi-dev
node test/replay-history.ts            # 只读比较现有历史执行，不调模型
```

自检统计 `src/` 下所有 `.ts` 和 `.md` 文件去掉空白字符（JS 正则 `\s`）后的字符总数，超过 155,000 即失败；行数仅作参考。测试用临时仓库、本地裸仓库、模型 / Pi / 部署替身；不安装 launchd。R1 原有的 `node tools/replay-r1.ts` 另行运行，会调用真实评审、写报告，不属于自检。
