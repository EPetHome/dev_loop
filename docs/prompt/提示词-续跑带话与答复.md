# 提示词：续跑带话、认出模型出错、答复

> 来源：PA 项目[方案-PA台账接手验收与用量](/Users/Admin/Desktop/personal%20agent/docs/prompt/方案-PA台账接手验收与用量.md)第五节之四和第八节（本人 11-14 定）。PA 的「停下接力」三张卡要用这三样；本卡只改 dev-loop。

## 目标

PA 以后会在飞书里替本人处理停下的任务：本人回一个数字，PA 调 dev-loop 续跑。现在有三处接不上：

1. **续跑后窗口里没人说话**：从「等你」续跑只改状态，留言「请在原开发会话继续」，开发窗口什么都没收到，任务一直干等，直到本人去窗口里打字。
2. **模型出错被记成「停下没交付」**：11-13 PA 会议纪要那次，开发方的模型服务半夜连续出错，最后一次「fetch failed」结束了这一轮，dev-loop 记成「停下没交付」等本人，和开发方停下来问问题分不开。
3. **答复没做**：开发方停下来问问题时，本人要能在飞书里回答，PA 把原话转给开发方；README 第 36 行写着「答复尚未实现」。

现状（11-14 协调方核实；行号会变，以函数为准）：

- `src/core/lifecycle.ts` 的 `resume`：会话还在、状态是「等你」时，转「开发中」、留言「已续跑，请在原开发会话继续」，不写任何要送进窗口的话。从「等你」续跑本来就允许会话还在（`running && s.state !== "input_required"` 那一行）。
- `src/hosts/pi.ts` 的 `refresh`：每秒看一次 `s.loop.pendingReturn`，状态是「开发中」、没有收尾进程时，`pi.sendMessage(..., {triggerTurn:true})` 送进窗口并开一轮，送完清空。评审后台退回、部署退回已经这样用（`src/cli/finish.ts`、`src/hosts/launch.ts` 写 `pendingReturn`）。Claude／Codex 走 `src/hosts/hook.ts`，要等下一次 Hook 才交接。
- `src/hosts/launch.ts`：会话不在时，接着原会话（`--session`）重开，带开场提示。
- `src/hosts/pi.ts` 的 `agent_before_settle`：只把最后一条回复的文字交给 `settle`，丢了 Pi 记下的结束原因。Pi 会话记录里每条回复有 `stopReason`（`stop`、`toolUse`、`error` 等），出错时带 `errorMessage`。11-13 那次：86 条回复里 10 条 `error`，记成「停下没交付」那一刻正是一条 `fetch failed`。
- `src/core/settle.ts`：没交付时，有改动且没催过就催一句「尚未交付」，否则 `waitFor(dir, "停下没交付", ...)`。
- `src/core/store.ts`：`WaitReason` 现有五种。
- 评审输入在 `settle.ts` 拼（有「## 开发方交付说明」一节）；评审提示 `src/core/review-prompt.md` 第 6 行列出输入清单。
- `交付` 已支持 `--text-file`。

## 做完后的行为（以此为准）

**续跑带话**

| 情形 | 结果 |
|---|---|
| `续跑 <执行编号> --话 文本`（或 `--text-file 文件`），会话还在 | 照现在的规则续跑；同一步把这段话写进待送；Pi 插件送进窗口并开一轮，原文一字不差，只送一次 |
| 同上，会话已不在 | 接着原会话重开，这段话放进开场提示 |
| 续跑不带话 | 和现在完全一样 |
| 宿主是 Claude 或 Codex | 照样写进待送，交给现有 Hook 交接；状态和回执写「未送达，需在窗口里说」，不报已送达 |
| 话是空的 | 拒收，不续跑 |

**认出模型出错**

| 情形 | 结果 |
|---|---|
| 本该记「停下没交付」，而最后一条回复的结束原因是 `error` | 改记新的等待原因「模型出错」，消息里带出错原话（`errorMessage`） |
| 结束原因是 `stop`，或拿不到结束原因（旧会话、别的宿主） | 照旧记「停下没交付」 |
| 「催一句尚未交付」 | 规则不变 |
| 「模型出错」状态下续跑（可以带话） | 会话还在也能续跑，和其他「等你」一样 |

**答复**

| 情形 | 结果 |
|---|---|
| `答复 <执行编号> --话 文本`（或 `--text-file 文件`），状态是「等你」 | 原话追加进任务目录的答复记录（只追加，带时间）；然后按「续跑带话」续跑，送进窗口的是「本人答复：<原话>」 |
| 之后的评审 | 评审输入多一节「本人答复」，按时间列出全部答复，原文一字不差；评审提示写明：答复是本人在开发途中的决定，和提示词冲突时按答复判 |
| 公开状态 | 带答复条数 |
| 状态不是「等你」（开发中、收尾中、已完成、已停止、已放弃） | 拒收，说明原因，不写记录 |
| 话是空的 | 拒收 |

## 边界

- 答复不改提示词、验收标准，不改它们的哈希，不作废已有结论（设计底线：结论只绑定 commit、提示词和验收标准）。
- 不放宽卡的范围和任何检查；不加别的拒绝点（不设长度上限）。
- 不加自动重试、不加定时器。
- 只改 `src/**`、`test/**`、`README.md`；README 同步写上三样（命令、等待原因、答复记录）。
- 测试用替身宿主和构造的状态、会话记录，不开真会话。

## 验收标准

A1. 操作：构造「停下没交付」、Pi 会话还在的任务，执行续跑并带一句话
    预期：状态转「开发中」；Pi 插件替身收到一次送话，原文一字不差、开了一轮新的；待送随即清空
A2. 操作：构造会话已退出的同样任务，续跑带话
    预期：重开命令带原会话文件，开场提示里有这句话
A3. 操作：续跑不带话
    预期：状态、留言、回执和现在完全一样
A4. 操作：构造最后一条回复 `stopReason: "error"`、`errorMessage: "fetch failed"`、没交付、已催过一次的情形
    预期：等待原因是「模型出错」，消息里有「fetch failed」；没有出现「停下没交付」
A5. 操作：最后一条回复 `stopReason: "stop"` 没交付；另构造回复里没有结束原因
    预期：都照旧记「停下没交付」
A6. 操作：「模型出错」状态、会话还在，续跑带话
    预期：能续跑，话送进窗口
A7. 操作：「等你」状态下答复两次
    预期：答复记录两行，只追加、带时间；两次都送进窗口，内容是「本人答复：<原话>」；之后的评审输入里有「本人答复」一节，两条原文一字不差；评审提示里有「冲突时按答复判」
A8. 操作：任务在开发中、收尾中、已完成、已放弃时各答复一次
    预期：都拒收，说明原因，答复记录不变
A9. 操作：宿主为 Claude、Codex 的任务续跑带话、答复
    预期：照样写进待送和答复记录；状态和回执写未送达，不报已送达
A10. 操作：续跑带空话、答复空话；再跑现有测试
     预期：空话都拒收、状态不变；现有测试照常通过
