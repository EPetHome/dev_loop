# 提示词：开发前约定收尾，评审通过后一条龙走完

## 目标

现在 dev-loop 走到「完成」就停，合入、部署要有人再运行一次命令，出了问题也没有退回和定位手段。这批让开发卡的 `flow` 能写到合入、部署、推送，评审通过后由程序按卡自动走完，不调用模型；部署坏了退回线上并退回开发方返修；一个需求拆成几张卡时能自动接力；开发时并行存基线，部署前后留痕。

行为以这两份文件为准，先读（用绝对路径，它们不在工作区里）：

- 需求：`/Users/Admin/Desktop/dev-loop/docs/需求-约定收尾一条龙.md`（「预期结果」、「验收标准」）
- 方案：`/Users/Admin/Desktop/dev-loop/docs/方案-约定收尾一条龙.md`（第三至十一节、第十二节之二至之四；第十二节开头「部署脚本」「迁移约定」「备份实现」和「其他」是 PA 的批次，本批不做）

这是一个流水批次：在本会话里按下面的顺序一次做完，中途不需要等人。每做完一段先跑自测，通过后再做下一段。全部做完后再交付一次。

| 顺序 | 内容 | 方案章节 |
|---|---|---|
| 1 | 开发卡 flow 校验、`after`、`next`、存进 `task.json`、启动时校验 | 第三节、第三节之二 |
| 2 | 新阶段、等待原因、`finisher`、`afterCommit`、`stepView`；`settle` 的收尾分支和不盖阶段；`续跑`、`交付` 的改动 | 第五节、第六节末尾 |
| 3 | `bin/loop 收尾`、试合并、部署成功后 dev 才前进、项目级排队；手工合入、部署进同一队列；宿主拉起独立进程 | 第四节、第六节 |
| 4 | 失败分流、退回开发方返修、`pendingReturn`；接力启动下一批；`结果.md`、待验数 | 第六节之二、之三，第三节之二 |
| 5 | `bin/loop 退回`、`deploy.env` | 第七节、第九节 |
| 6 | 留痕（`snapshot`、比较、评审材料的运行差异、`bin/loop 对比`）；陪跑；`bin/loop 释放` | 第十二节之二至之四 |
| 7 | 固定说明、命令帮助、README | 第十节、第十一节 |

## 已拍板

- flow 的完整顺序是 `开发评审, 测试, 合入, 部署, 推送`。不做项目级默认走法。
- 命令名 `收尾`、`退回`、`对比`、`陪跑`、`释放`，阶段名「收尾中」「已退回」，等待原因「收尾没走完」，字段 `deploy.env`、`snapshot`、`next`，都按需求和方案写，不改名。
- 收尾走完之前，对外 state 不报 `completed`。`loop-status/1` 的五种 state 不加新值。
- 写到部署的卡：先试合并，部署成功后 dev 才前进。部署用试合并的 commit。
- 接力：中间批不动 dev，下一批的起点是上一批的交付 commit，最后一批才合入、部署。
- 部署失败且线上已退回、试合并冲突：退回开发方返修，默认最多 2 轮。回退也失败、到上限、合入资格不足、推送失败：转「等你」。不原样重试。
- 卡上写了部署，项目必须登记 `cmd`、`check`、`rollback`。手工 `bin/loop 部署` 不要求 `rollback`，和现在一样。
- 退回只动线上，不动 dev，不用 `git revert`。
- 自动收尾绝不使用「接受未验证」。
- 收尾进程脱离开发会话，开发窗口关闭后继续运行。
- `停止` 不打断正在跑的部署脚本，跑完后不再进入下一步。
- 同一个 commit 只自动发起一次收尾。
- 同一项目的收尾、手工合入、手工部署、退回排队，不拒绝；排队等待期间心跳不能停。
- 陪跑和留痕失败只记录，不改状态，不影响开发、复测、评审、部署。
- 新增的拒绝点只有需求第十一节列的，以及方案里标明「无法执行」的，不多加。
- 依赖方向不变：`steps` 之间不互相引用；组合放在 `cli`；`hosts` 不引用 `steps`，用子进程拉起；core 只看 `after.length`、`next`。不新增依赖；src 不超过 2000 行。

## 边界

- 只改 `src/**`、`test/**`、`README.md`。不改 `docs/`、`bin/`、`plugins/`、`AGENTS.md`、`CLAUDE.md`，不改 PA 和旧 loop。
- 不碰 main。测试里不部署真实服务，不打开真实终端，不调用真实模型，不连真实远端：远端用临时裸仓库，部署脚本、快照脚本、评审和 pi 都用替身。
- 已有测试：不删用例，不放宽断言。只允许改这两处，并在交付说明里写明：
  - `test/cli.test.ts` 第 69–71 行：flow 写「部署」不再报原来的错，「提交」的提示文字更新。
  - `test/core.test.ts` 第 90 行：阶段数 19 改为 21。
- 确实还要改别的已有断言，在交付说明里逐条列出改了什么、为什么。
- 不写死等待秒数，用文件事件或现有的 `until`；全部测试不超过 2 分钟。
- 不做需求第十六节「不做」里的任何一项。
