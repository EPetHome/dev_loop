# W3-B-Pi窗口补充说明进评审

## 目标

用户直接在 Pi 开发窗口补充的话，后续静态评审也能看见。按本人 11-22 对 D4 的决定与 /Users/Admin/Desktop/dev-loop/docs/需求-验证闭环.md 第八节做 G7。

## 已拍板与边界

只覆盖 dev-loop 管理的 Pi 会话。查实际安装 Pi 的事件类型、来源区分与消息生命周期，在最靠近本人输入的可靠事件采集原文与时间到本执行的 窗口原话.jsonl。评审材料注明来源及权重。与正式提示词、验收标准冲突时标为需求疑问。禁止把来源不明的输入冒认为本人、禁止把路径展开或工具结果当成本人原话。原始输入作为数据，保留换行。正式要求、权限、结论绑定不随聊天改动。兼容无原话文件的旧执行。其他宿主按原方式处理。隔离宿主与评审替身自测。

## 验收标准

1. 在同一 Pi 会话中先收到自动开场，随后输入两段不同的多行补充，含重复字句和标点。记录和评审按顺序展示本人原文、时间；开场与工具输出不出现。
2. 使用答复、带话续跑、返修派发和会话恢复，系统自动送入的内容不算新的本人输入。故意连续输入相同原话两次，按两次真实输入保留。
3. 将与正式要求冲突的窗口话送进评审，材料明确冲突应列疑问；不创建新的必修或改变正式标准，也不单凭文字触发任何命令。
4. 没有窗口原话的旧执行、独立 Pi 会话、Claude 或 Codex 沿用既有行为；仅用户聊天变化时仍可沿用已绑定的正式检查。
