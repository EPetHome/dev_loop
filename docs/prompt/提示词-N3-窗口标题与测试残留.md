# N3-窗口标题与测试残留

## 目标

修两个新版上线后发现的 bug，一张卡做完：

1. 卡已经完成，Pi 窗口标题和状态栏却仍显示「【开发中】」，本人误以为 loop 和 PA 错乱。问题单：`issues/【bug】卡已完成时Pi窗口标题仍显示开发中.md`。
2. 跑完自检后留下孤儿进程（`launch.ts` 加 `fake-launch.cjs`，父进程是 launchd），测试临时目录已经删了，进程还在。问题单：`issues/【bug】自检测试结束后留下孤儿开窗进程.md`。

## 已拍板

1. 窗口标题和状态栏里的阶段，直接用 `loop 查询` 现算阶段的同一个函数，不在插件里另写判断。至少要正确显示「等你」「本人中止」、正在跑的那一步、「完成」，以及完成之后的合入、部署、释放等阶段。
2. 孤儿进程：找出是哪条测试启动了 `launch.ts` 和 `fake-launch.cjs` 却没有回收，在测试收尾时结束整个进程组。再在自检收尾加一项检查：命令行带本次测试临时目录的进程要一个不剩，否则测试失败。
3. 不改推进逻辑，不加依赖。体量检查照常（上限 155,000 非空白字符），碰线就用 `loop 提问` 停下，不许压缩代码凑数。

## 边界

- 只改开发卡 scope 里的文件。不改需求文档、写法文档、AGENTS.md、`issues/`、`tools/`。
- 孤儿进程如果查明是产品代码（开窗或启动逻辑）本身没有回收子进程，可以修产品代码，但要在交付说明里写清楚。
- 测试只结束自己启动、命令行能对上本次临时目录的进程，不凭 PID 或进程名去结束别的进程。

## 验收标准

A1. 操作：一张卡的账本写入「完成」后，让插件刷新一次窗口标题
    预期：标题和状态栏的阶段与 `loop 查询 --brief` 一致，显示「完成」，不显示「开发中」
A2. 操作：接着对这张卡写入「合入」，再刷新一次
    预期：标题阶段跟着 `loop 查询` 变成合入后的阶段
A3. 操作：用 A1 的测试在起点提交上跑
    预期：失败，说明这条测试能抓住原 bug（修前失败、修后通过）
A4. 操作：跑完 `node --test test/*.test.ts`，再用 `ps` 查命令行带 `dev-loop-test-` 的进程
    预期：一个都没有
A5. 操作：运行 `node --test test/*.test.ts`
    预期：全部通过，总耗时不超过 2 分钟，体量检查通过

## 完成后需要提供

- A1–A4 对应的测试名，A3 的修前失败记录。
- 孤儿进程是哪条测试漏了回收、漏在哪里。
