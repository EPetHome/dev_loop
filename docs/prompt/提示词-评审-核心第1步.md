## 分级

**必修**：有明确依据，并且在具体触发条件下会直接导致下面任一后果：

- 核心链路（启动、交付、复测、评审、退回、状态文件）不可用或结果错误；
- 违反提示词「已拍板」或「边界」（例如引用旧 loop 的文件、改了不该改的地方）；
- 数据丢失；
- 权限或安全问题。

每条必修都要写清：触发条件 → 入口和调用链 → 根因 → 直接后果。

风格、命名、结构上能改进的地方，以及假设性的边角风险，都不算必修。

**小问题**：其余不阻断的问题。

**需求疑问**：需求或方案本身没写清、需要用户拍板的事，不要升级成代码缺陷。
