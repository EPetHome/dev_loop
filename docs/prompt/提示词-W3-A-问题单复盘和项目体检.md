# W3-A-问题单复盘和项目体检

## 目标

为协调方提供独立于开发核心的项目工具。每次新开工前，能读出上批出了什么问题、有没有再发生、哪些有证据可以关单，和项目还缺什么。本人 11-22 确认 D10：工具放在 dev-loop 仓库。按 /Users/Admin/Desktop/dev-loop/docs/需求-验证闭环.md 第十、十一、十二、十三节，以及 docs/方案-验证闭环.md 第七节实施 G5、D19、G17。

## 已拍板与边界

在仓库 tools/ 下实现协调命令，根 README 说明参数和结果，给 PA 的开工入口一份稳定调用方式。读取项目已登记的问题单、批次、功能地图、模板、执行记录与公开查询。核心不导入工具，工具不改产品代码、用户规则、技能、测试预期或上线状态。按项目隔离，项目路径由调用方明确提供。复盘从真实已有格式取数，保留原始出处。关单、候选确认、未确认状态的写入应可重试、不覆盖用户改动；需要批准的规则必须交由本人决定。使用系统临时目录的隔离项目做读写测试，真实项目不作试验材料。批次与问题单各按其自身规则处理。

## 验收标准

1. 给定两项目的交错历史，为其一开工，收集该项目上一批的必修、小问题、需求疑问、测试失败、停下原因、运行差异、收尾笔记和已记录的窗口原话。每项能追到已有来源；缺失记录如实显示。
2. 用同一文件、场景或停下原因重放不同批次，第一次记信号，第二次列候选与落位建议；重新读取同一次执行不重复计数。接受不处理、已批准和批准后再次出现能相互区分。
3. 从批次、部署、检查事实计算问题单状态，修复批通过、归因字段齐全、有目标防复发证明（或明确写明拦不住）才可关单并移动入历史；缺证据保留原文。有本人授权要求的项仍须取得相应事实。
4. 同项目下次开工或部署满七天，以较早者结束无反馈的人工提醒，保留每条授权未做和原反馈。已有通过、不通过、有后续反馈及旧格式都能读；部署时间未知不能推定已满七天。
5. 检查功能清单、功能地图和脚本，分别指出缺少验法、已删除或不存在的功能、脚本缺失或失配，以及可能漏选的受影响路径。非场景验法也有效，删除时检查所需的反向场景。给出提示，不添加开工门槛。
6. 在新旧项目按模板检查跑法、判断依据、工具、管理记录四类，报告实在、缺少或有原因暂缓的条目。暂缓的 REVIEW.md 不变成拒绝点。
7. 按当月第一次开工或显式查询现场生成有日期的月度汇总与剪枝候选。按方案口径给出介入、流程失败、首轮必修、返修轮次、漏网、批次耗时，并说明误报等指标的未知和分母；重复开工不重复写入。避开独立定时服务。
8. 操作前预览项目和变动；模拟中断、同时重试及同名历史文件时，原文和证据能保留，产物可追溯。
