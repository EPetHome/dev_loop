# dev-loop 核心第 1 步：开发 → 复测 → 评审一圈

## 目标

在当前目录 `/Users/Admin/Desktop/dev-loop` 从零实现新核心的一圈，覆盖单任务开发卡：

```
启动 → 开发会话 → 交付 → 会话停下 → 复测 → 评审 → 退回或完成
```

同时写出 PA 约定格式的状态文件。入口是 `bin/loop`。

必读：
- `docs/需求-开发复测评审核心.md`，重点看「预期结果」「底线规则」「对 PA 的接口」三节。
- `docs/方案-开发复测评审核心.md`。本步按第二到七节、第九节实现，细节以方案为准。
- PA 约定（只读）：`/Users/Admin/Desktop/personal agent/docs/requirements/需求书-PA.md` 第七节「统一接入约定」中的状态报告字段。
- 可复用的材料（只读）：方案第二节表格里列出的旧 loop 文件，位于 `/Users/Admin/Desktop/loop`（或其 `legacy/` 下）。只读这几个，不要通读旧 loop。

## 已拍板

1. **从零实现。**
   - 不引用旧 loop 的任何文件。需要的函数复制过来并精简。
   - 目录和依赖方向按方案第二节，并加一个测试检查依赖方向。

2. **一圈的规则按方案第五节。**
   - **交付**：开发方在会话里运行 `bin/loop 交付`。
     - 有 scope 外的改动就拒绝，并列出这些文件。
     - scope 内的改动提交到任务分支。
     - 与上次交付是同一个 tree 时，不造新提交。
     - 命令马上返回。
   - **会话停下**：三家宿主共用一个处理函数，依次判断：
     1. 交付有效，就往下走。
     2. 交付后又改了，就提醒重新交付，这不计入退回次数。
     3. 这个 commit 已经检查过，直接沿用结论。
     4. 依次做复测、评审，结果是退回或完成。

     停下但没交付时：有改动就提醒一次，再停就转「等你」；没有改动直接转「等你」。
   - **复测**：在 worktree 里用 `sh -c` 跑卡上的测试命令，有时限。
     - 失败就退回：命令、输出最后 60 行、含 error/fail 的行。
     - 测试写的是 `无：原因` 时，记为没验证，继续评审。
   - **评审**：输入只给提示词、验收标准（有的话）、diff、新增文件、交付说明、复测结果；第 2 轮起再加上一轮的必修和开发方的回复。
     - 只退回必修。
     - 调用重试一次仍然失败，就记为失败，类别是「临时故障」。
     - 评审规则按方案第六节修改，放到 `src/core/`。
     - 默认 astra、思考档 xhigh。
   - **结论只看 commit**：`checks.jsonl` 里这个 commit 有复测通过（或没验证）、评审通过，并且提示词和验收标准的哈希一致，就算检查过。聊天、原目录文档、构建产物、证据文件在不在，都不影响结论。
   - **上限**：复测退回 3 次，评审必修 4 次，分开计数，卡上的 limits 可以覆盖。到上限转「等你」，并在 message 里写清可选的做法。
   - **时限**：复测 20 分钟，评审每轮 60 分钟，可以覆盖。

3. **数据按方案第四节。**
   - 根目录是 `~/.dev-loop/tasks/<执行编号>/`，可以用环境变量覆盖。测试里一律指向临时目录。
   - `status.json` 的 state 只用 `working`、`input_required`、`completed`、`failed`、`cancelled` 五个值。
   - 自身失败按 PA 的六类错误归类。

4. **命令。**
   - `启动`：几秒内返回执行编号；之后在后台建 worktree 和任务分支、复制 localFiles、跑 `.autoreview.json` 里可选的 `setup`、用 `bin/pi-dev` 打开 pi 会话。
   - `交付`。
   - `查询`：含 `--all --brief`，结果带 `complete: true`。
   - `续跑`、`停止`、`放弃`。
   - 遇到多任务卡，或 flow 里有验收、提交、部署的卡：直接拒绝，写明第几步才支持，不建执行目录。
   - 卡格式不变（version 1），换算按方案第九节。

5. **宿主（只做核心链路和协调方对接）。**
   - **pi**：扩展放在 `src/hosts/pi.ts`。
     - `session_start`：登记会话进程身份，开始 60 秒心跳。
     - `agent_before_settle`：调用处理函数；需要退回时返回 `{ entries: [custom_message], continue: true }`。
     - `session_shutdown`：停止计时。
     - `bin/pi-dev` 参照旧 loop 的 `bin/pi-dev`：默认 sol、思考档 max、带权限扩展，但只加载 dev-loop 自己的扩展。
   - **Claude/Codex**：`hosts/hook.ts` 是薄入口，转给 `src/hosts/hook.ts`。
     - `SessionStart`：登记。
     - `PostToolUse`：心跳，至少间隔 60 秒。
     - `Stop`：调用处理函数；需要退回时输出 `{"decision":"block","reason":…}`。
     - 不处理 `UserPromptSubmit`。
     - `plugins/dev-loop/`：只写好插件清单和 `hooks.json`，不安装。
   - **开发方怎么找到自己的任务**：优先用环境变量 `LOOP_TASK_DIR`，没有时按当前目录匹配 worktree。打开会话时在开头告诉开发方：做完后运行 `<绝对路径>/bin/loop 交付`。

6. **计时与总结。** 每一步都计时，写进 `checks.jsonl` 和 `status.json`。`summary.md` 控制在一屏以内，列出每一步的结论和耗时，分开列开发、复测、评审、等你、dev-loop 自身。

## 边界

- 不做合入、整合、验收、部署、答复。
- 不新增依赖包，不引入框架、构建系统或通用调度器。`src/` 约 2000 行以内，不含测试；超出要说明原因。

## 验收标准

A1. 操作：在临时仓库里用单任务卡执行 `bin/loop 启动 <卡> --json`。
    预期：几秒内返回执行编号；`status.json` 已经存在，state 是 working；随后 worktree 和任务分支都建好。

A2. 操作：模拟开发方在 worktree 里改 scope 内的文件，运行 `bin/loop 交付`；再分别用 pi 的 `agent_before_settle` 和 Claude 的 `Stop` 触发停下。
    预期：先跑卡上的测试命令，再调用评审替身；评审通过后 state 是 completed，`checks.jsonl` 里有这个 commit 的复测通过和评审通过两条记录。

A3. 操作：交付一个会让测试失败的改动，然后停下。
    预期：不调用评审。退回内容包含命令、输出末尾和错误行。pi 返回 `continue: true`，Claude 输出 `decision` 为 `block`。

A4. 操作：评审替身返回必修，开发方修完再交付；另外构造一次连续退回到上限的情况。
    预期：退回只包含必修，每条有「文件:行」和触发条件。再交付时先复测、后评审。到上限后 state 是 input_required，message 写清原因和可选做法。

A5. 操作：评审通过后，修改原目录的 `AGENTS.md`，在 worktree 里生成被忽略的构建产物，然后查询并再次停下。
    预期：仍然是 completed，不重跑复测和评审，`summary.md` 里写「沿用」。

A6. 操作：改一个 scope 外的文件，然后运行 `bin/loop 交付`。
    预期：拒绝，并列出越界的文件，不生成 commit。

A7. 操作：交付之后又改了 scope 内的文件，然后停下。
    预期：退回一句提醒，要求重新交付；不计入退回次数，也不跑复测。

A8. 操作：停下时既没有交付，也没有任何改动。
    预期：state 是 input_required，message 是开发方的最后一段话。

A9. 操作：执行 `bin/loop 查询 --all --brief --json`，然后查看 `status.json` 和 `summary.md`。
    预期：
    - 查询一次返回全部执行，并且带 `complete: true`；
    - `status.json` 含方案第四节的全部字段，seq 每次更新都递增，`loop.session` 里有宿主、进程号和启动时间；
    - `summary.md` 在一屏以内，列出了各步的结论和耗时。

A10. 操作：分别用多任务卡和 flow 含「提交」的卡执行 `启动`。
    预期：都被明确拒绝，说明不支持以及第几步才支持；不建执行目录。
