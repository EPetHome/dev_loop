# W2-C 让开发会话加载本项目的验证手册

## 目标

开发者能在 Pi 中拿到项目维护的 verify skill，知道怎样启动、操作和取证。以 /Users/Admin/Desktop/dev-loop/docs/方案-验证闭环.md 第七节 W2-C 与需求 G10、G21 为准。开工前由协调方核对 PA 第二波交付的手册实际位置。

## 已拍板与边界

只对已登记、当前项目确实存在的验证手册使用 Pi 的显式 --skill 参数。核对本机 Pi 版本、CLI 对应参数以及项目本身的发现路径。保留既有权限扩展、自动执行方式、工具、模型、工作目录和独立只读评审配置。不开全局技能自动发现。未接入的项目沿用现有入口。改 bin/pi-dev、必要的 src/hosts/**、现有 CLI 测试、README.md 和 docs/参考-运行细节.md；用当前工作区中的实际文件，不把 PA 绝对路径写死。用隔离启动替身验证，正式复测仍走项目测试命令。

## 验收标准

1. 从普通开工和续跑入口准备有手册的工作区，实际开发启动参数都只附带该项目的验证手册；带空格的路径仍作为一个参数传入，既有权限与模型配置有效。
2. 用没有手册的旧项目开工，原开发会话可以照常启动；其他项目的手册和无关全局技能均不加载。
3. 启动开发后检查加载回执或可观察的技能清单，记录已加载手册与本项目路径的对应；区分参数已构造、宿主已加载和真实业务体验。
4. 复测仍调用卡上的测试命令，独立静态评审沿用只读入口。
