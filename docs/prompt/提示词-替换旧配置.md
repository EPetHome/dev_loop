# 用 dev-loop 替换旧 loop 的本机配置

## 目标

旧 loop（`/Users/Admin/Desktop/loop`）已经废弃，把本机配置换成 dev-loop（`/Users/Admin/Desktop/dev-loop`）。只改配置，不改任何代码。

## 要做的事

1. **备份。** 先把下面三个文件复制一份到同目录，文件名后加 `.bak-20261109`：
   - `~/.claude/CLAUDE.md`
   - `~/.claude/settings.json`
   - `~/.codex/config.toml`
2. **全局 `~/.claude/CLAUDE.md` 的「pi 提示词」一节**，只改这两行，其他内容一字不动：
   - 「会变的写法看外部文档…」这一行改成：
     需求、提示词、验收标准、开发卡、问题单的写法 → `/Users/Admin/Desktop/dev-loop/docs/写法-需求提示词与验收标准.md`；命令、字段、启动 → `/Users/Admin/Desktop/dev-loop/README.md`；项目自己的模型、工具和启动细节 → 项目的启动说明（Promate：`coding/prompt/pi启动方式.md`）。
   - 「评审交给 loop…」这一行改成：
     评审交给 dev-loop：不另写复核提示词，跑完读 dev-loop 的总结（`~/.dev-loop/tasks/<执行编号>/summary.md`）再向用户汇报。
3. **停用旧插件，但不卸载、不删缓存：**
   - Claude Code：把 `~/.claude/settings.json` 里 `enabledPlugins` 的 `"autoreview@autoreview-local"` 改成 `false`。
   - Codex：把 `~/.codex/config.toml` 里 `[plugins."autoreview@autoreview-local"]` 下的 `enabled = true` 改成 `false`。
4. **让 dev-loop 插件可以安装：**
   - `plugins/dev-loop/hooks/hooks.json` 里的命令目前用 `${CLAUDE_PLUGIN_ROOT}/../../hosts/hook.ts`。插件安装后会被复制到缓存目录，这个相对路径会失效。改成绝对路径 `/Users/Admin/Desktop/dev-loop/hosts/hook.ts`，`node` 的路径保持原样。
   - 参照旧 loop 的 `/Users/Admin/Desktop/loop/.claude-plugin/marketplace.json`，在 dev-loop 根目录新建 `.claude-plugin/marketplace.json`。市场名 `dev-loop-local`，插件 `dev-loop`，source 为 `./plugins/dev-loop`。如果旧 loop 根目录还有给 Codex 用的市场清单（比如 `.agents/plugins/`），同样照着做一份。
5. **安装 dev-loop 插件：**
   ```bash
   claude plugin marketplace add /Users/Admin/Desktop/dev-loop
   claude plugin install dev-loop@dev-loop-local
   CODEX_BIN='/Applications/ChatGPT.app/Contents/Resources/codex-cli/bin/codex'
   "$CODEX_BIN" plugin marketplace add /Users/Admin/Desktop/dev-loop
   "$CODEX_BIN" plugin add dev-loop@dev-loop-local
   ```
   命令报错时，先看 `--help` 找到正确的写法再重试，不要猜。实在装不上的，在最后说明里写清卡在哪一步、原始报错是什么。

## 边界

- 不改旧 loop 和 PA 的任何文件，也不改 dev-loop 的 `src/`、`test/`、`bin/`。
- 不删除任何缓存、运行数据或旧配置；只改上面列出的内容。
- 不 commit，不推送。
- Codex 装好插件后，需要用户在 Codex 里输入 `/hooks` 才能信任新的 Hook，这一步你做不了，写进最后的说明即可。

## 冒烟（只做这一项）

在一个不带 `LOOP_TASK_DIR` 环境变量的临时目录里，把一个最小的 Stop 事件 JSON 通过 stdin 交给 `node /Users/Admin/Desktop/dev-loop/hosts/hook.ts`，确认它不报错、也不拦截。
