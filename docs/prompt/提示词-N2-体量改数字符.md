# N2-体量改数字符

## 目标

体量检查现在只数 `src/` 的行数，开发为了过线会把几行合成一行：N1 正好压在 2000 行，长行越挤越多。本批把量法改成数非空白字符，让合行凑数没有用；同时把为压线合出来的长行拆回去。

问题和数据见 `issues/【bug】体量硬上限只数行数，开发为过线合并代码行.md`。

## 已拍板

1. 量法：统计 `src/` 下全部 `.ts` 和 `.md` 文件，去掉所有空白字符（JS 正则 `\s`）后数字符，上限 **155,000**，超过就失败。失败消息写出实际字符数和上限。行数照常打印，只作参考，不参与判断。
2. 拆行：`src/` 里超过 160 字符的行拆到 160 字符以内，只改换行和缩进，不改逻辑、命名、注释和文案。注意自动分号插入：不在 `return`、`throw`、`break`、`continue` 后面断行，也不在 `++`、`--` 前面断行。字符串、正则等确实拆不开的行保留原样，在交付说明里逐条列出。
3. 不新增依赖，不引入格式化工具，不加单行长度的硬检查。
4. README「自检」一节里「不超过 2000 行」的说法，改成新的量法和上限。

## 边界

- 只改开发卡 scope 里的文件。不改需求文档、写法文档、AGENTS.md、`issues/`、`tools/`。
- 除了拆行，不改 `src/` 的任何行为。
- 本批如果碰到体量上限，用 `loop 提问` 停下来报给本人，写明现值、上限和可以砍的候选。不许靠压缩代码、删注释、缩短命名或把代码挪到不计数的位置来过线。

## 验收标准

A1. 操作：在 `src/` 任一 `.ts` 文件里把相邻两行合成一行（只删换行和缩进），然后跑体量测试
    预期：报出的字符数和合并前一样，通过或失败的结果也和合并前一样
A2. 操作：让 `src/` 的非空白字符超过 155,000（例如在临时副本里加一个文件），然后跑体量测试
    预期：测试失败，消息里有实际字符数和上限 155,000
A3. 操作：对比起点提交和交付提交的 `src/`，每个文件都去掉全部空白字符后比较内容
    预期：逐文件完全相同
A4. 操作：统计交付后 `src/` 里超过 160 字符的行
    预期：0 行；或者只剩交付说明里逐条列出、确实拆不开的行
A5. 操作：运行 `node --test test/*.test.ts`
    预期：全部通过，总耗时不超过 2 分钟

## 完成后需要提供

- 拆行前后对比表：行数、非空白字符数、超过 160 字符的行数、超过 200 字符的行数。
- A1、A2 对应的测试名。
- 保留下来没拆的长行清单，以及每一行拆不开的原因。
