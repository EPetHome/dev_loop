## 已拍板

- 命令名、参数名、输出字段、阶段名称、状态栏和标题的文字格式、`deploy` 字段名、环境变量名、提交信息格式，都按需求和方案写，不改名、不增减。
- 推送默认关闭：不加 `--推送` 就不推。不加 `--force`，不推标签，不拉取，不重试。
- 部署：脚本是仓库内可执行文件的相对路径，在被部署 commit 的临时检出里运行，跑完删除检出。cmd 或 check 失败、且登记了 rollback 时，自动运行一次 rollback。不重试。
- 密钥扫描只用方案第六节的内置规则，不加 `password=` 这类通用规则，不加放行开关；命中时不输出命中的内容。
- pi 阶段显示：`session_start` 时保存 `ctx`，每秒读一次 `status.json`，有变化就调用 `ctx.ui.setStatus("dev-loop", …)` 和 `ctx.ui.setTitle(…)`。可参照旧 loop `/Users/Admin/Desktop/loop/kernel-pi.ts` 第 29–50、78–80 行的做法，但不引用它的代码。
- 对外 state 只在一种情况下改变：「等你」时用 `--接受未验证` 合入成功，改为 `completed`。其他情况下，合入、推送、部署只在 state 为 `completed` 时改阶段；在其他 state 下只追加记录。
- 依赖方向不变：`steps` 之间不互相引用，「合入后推送」由 `cli` 先后调用两者完成；core 里不出现「合入」「推送」「部署」这些步骤名，只放通用函数和阶段常量。不新增依赖；src 不超过 2000 行。
