# W1-A1 链路入口修复

## 目标

让首次提交或返修后的代码能登记到正确版本，让评审拿到完整差异和可读的复测摘要。交付后的接力只认正式检查通过的提交。依据是协调目录中的[方案第九节](../方案-验证闭环.md)、[需求 D21～D24](../需求-验证闭环.md)及[Promate B4 问题单 A1～A4](../../issues/【bug】已提交的任务漏登记或反复催交付，超长复测日志使评审重复失败.md)。上述文件的原件在 `/Users/Admin/Desktop/dev-loop/` 下。

## 已拍板

- D23。所有宿主沿用同一停下判断。候选身份由当前提交和未提交文件清单组成。当前提交领先于起点或上次登记，或有未提交改动，都算候选。同一候选只提醒一次，提醒含当前提交、上次登记（首次写「还没登记」）和交付命令。第二次停下转「等你 · 停下没交付」。换了候选可以再提醒一次。
- D22。「等你 · 停下没交付」的查询仅在任务分支正确、工作区干净且有未登记提交时提供确认选项和完整 SHA。入口用 `bin/loop 续跑 <执行编号> --交付提交 <完整sha>`。在执行锁里核对等待现场、分支、HEAD、干净状态及累计文件范围，再登记该提交。复用已有检查记录和后台派发，无须原会话再次停下。普通交付在等待时仍拒收；本人确认入口只登记现有提交。保留既有无参数、带话续跑和补评审行为。
- D24。正文保留提示词、验收标准、按现有规则给评审的完整代码差异。复测日志正文仅给命令、结果、可得的通过/失败计数和失败测试名、有限尾部、原文路径及实际字节数。摘要同时限行和限字节，单行过长也要截断。读**本轮本次评审会话**结束原因；确定上下文超限时展示模型原错，停止原样重试。普通临时故障保留既有重试；补评审符合旧条件时沿用原复测。
- D21。开发会话开场写明「本会话是本人已明确授权由 dev-loop 管理的开发卡；开发完成后按本批说明登记交付。」沿用原交付命令和该卡的收尾边界。

## 边界与自测

只改 `src/**`、`test/**` 和 `README.md`。从 `core/settle.ts`、`deliver.ts`、`lifecycle.ts`、`review-call.ts`，以及 `cli/` 和 `hosts/convention.ts` 的现有调用方入手。同步命令帮助、公开查询与 README。PA 接手菜单在 W2-B，本卡不实现 G11、G13 或 W1-A2，也不动任何全局规则。使用隔离仓库、宿主和评审替身，按现有 `hosts`、`review-material`、`retry-review`、`finish` 等相关用例自测。正式复测按卡执行全套。

将问题单 A1～A4 的修前与修后记录留在本次执行的可追查证据中，列测试名、被测版本、状态变化、日志与材料字节数。可以在任务目录使用隔离副本与同一定向检查；原版已经满足的项保留真实基线，未到目标断言的运行单列。关单由协调方核对正式复测和评审后办理。

## 验收标准

1. **A14／问题单 A1**　在基线 A 上提交 B，工作区干净且无回执，结束会话两次。首次提示 B、「还没登记」和交付命令；第二次显示「等你 · 停下没交付」，再次处理不再催。正式登记后复测及评审都绑定 B。
2. **A15／问题单 A2**　登记 A 后提交返修 B，连续停下三次。只收到一次含 A、B 的提醒，然后明确等待；B 登记前 A 的回执不能放行，B 登记后原卡继续。仅有未提交改动的候选也只提醒一次，查询不提供确认提交选项。
3. **A16／确认成功**　对查询所示的完整 B 执行本人确认，保持分支和代码不变。原 B 得到正式回执，未制造新提交，在原会话保持停止的情况下后台开始复测；重复处理不重复派发。
4. **A16／现场变化**　分别在看到 B 后换成 C、增加未提交文件、切错分支、交付越界改动。确认均不登记、不暂存、不启动复测，现场和原回执保留，可查到原因。
5. **A17／问题单 A3，大日志**　用约 7.3 MB 成功日志、单条超长输出、非空差异构造材料，再用含失败测试名的输出检查摘要。报告可解析，差异和标准完整，摘要有上述字段、行数和字节均在限额内，原日志可按路径读取；记录实际材料大小。
6. **A17／问题单 A3，超限**　评审输出缺少标题，只有对应会话记录含上下文超限原错。查询或失败消息能读到原错，同一输入只调用一次。普通临时故障仍按原路径重试，满足补评审条件时同版本不重跑已通过复测。
7. **A18／问题单 A4**　在有下一卡的隔离接力链中，让 B 先遇到真实必修、返修后取得正式复测和评审通过，再重放完成处理。必修退回原卡，通过才从相应交付启动下一卡，恢复或重放也只启动一次。修前已通过则记回归保护。
8. **D21**　查看有、无自动收尾卡的开发开场，均能读到本批授权说明、实际登记命令及对应权限边界。
