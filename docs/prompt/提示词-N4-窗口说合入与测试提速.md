# N4-窗口说合入与测试提速

## 目标

新版上线后，本人反映「看不懂、什么都有问题」。这一批修其中两处：

1. **本人在 Pi 窗口里说「合入」没有用。** N3 完成后，本人在窗口里打了「合入」（账本里已经记成窗口原话），开发方回答「这里不允许合入，请去普通终端执行……」。本人只看这个窗口，不应该再被打发去别处敲命令。
2. **自检越来越慢。** 复测耗时：N1 47–93 秒，N2 101 秒，N3 127 秒，已经超过项目规则的 2 分钟。最慢的是部署相关测试，每条 9–10 秒。

## 已拍板

1. 卡已完成（复测、评审都通过，没有在等本人）以后，本人在这张卡的 Pi 窗口里提交的原话，去掉首尾空白后**恰好是「合入」**，就当作本人的合入意图：账本记一条意图并附原话，然后调合入工具，只合本地 dev，不推送、不部署。合入工具照旧自己核对放行证据，不信调度器。
2. 只认卡完成以后提交的这一句。完成之前说的「合入」，以及「合入吧」「先别合入」这类别的说法，一律不当意图，照旧只是窗口原话。同一句原话只合入一次。
3. 合入的结果（成功给出合入提交，拒绝给出原因）要让本人在这个窗口里看得到：窗口标题变成合入后的阶段，同时往窗口发一条说明。开发方的开场说明里写明：本人在窗口说「合入」由 dev-loop 处理，开发方不要自己去跑合入命令，也不要让本人去终端执行。
4. 自检提速到全套 90 秒以内（留出机器忙时的余量）。等待和超时一律改用可注入的时钟或配置调小，不删测试、不放宽断言、不跳过用例。测试条数不能比起点少。
5. 不加依赖。体量上限 155,000 非空白字符；碰线就用 `loop 提问` 停下，不许压缩代码凑数。

## 边界

- 只改开发卡 scope 里的文件。不改需求文档、写法文档、AGENTS.md、`issues/`、`tools/`、PA。
- 窗口原话的采集方式不变（N1 的插件已经记了），这批只加「完成后恰好『合入』→ 合入意图」这一条解释。
- 不改其他意图的写入方式，不改 PA 用的命令和回执。

## 验收标准

A1. 操作：一张卡复测、评审都通过以后，本人在它的窗口里提交「合入」
    预期：账本里有一条附原话的合入意图和一条合入结论；本地 dev 上有合入提交，没有推送；窗口里能看到合入提交号，标题是合入后的阶段
A2. 操作：卡还在评审中时，本人在窗口里提交「合入」；之后评审通过
    预期：评审中那句不当意图；评审通过以后也不会因为那句旧原话自动合入（转换类：时间先后）
A3. 操作：A1 之后，tick 再跑两次
    预期：只有一次合入，不出现第二条合入意图或合入结论（转换类：重复）
A4. 操作：卡完成后，本人在窗口里分别提交「合入吧」「先别合入」
    预期：都不合入，只记为窗口原话
A5. 操作：往账本里手工加一条「完成」，这个提交其实没有评审通过，然后本人在窗口里提交「合入」
    预期：合入工具拒绝，窗口里能看到拒绝原因，`loop 查询` 报出缺证据的记录
A6. 操作：运行 `node --test test/*.test.ts`
    预期：全部通过，总耗时 90 秒以内，测试条数不少于起点

## 完成后需要提供

- 提速前后的总耗时、最慢 5 条测试的耗时对比，测试条数对比。
