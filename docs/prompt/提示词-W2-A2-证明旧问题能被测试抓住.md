# W2-A2 用相同测试证明旧问题能被抓住

## 目标

交付后协调方能用一条命令拿到旧版与修复版的实测记录，判断能否关闭具体问题单。依据 /Users/Admin/Desktop/dev-loop/docs/方案-验证闭环.md 第六节、第十节 A8、A9 和需求 D9。复用上一批的结果格式与现有临时检出工具。

## 已拍板

新增可选 tasks[].proofs 和独立的 bin/loop 证明 <执行编号>。启动时保存声明、解析旧版完整 SHA，默认是开工起点。执行时锁定本次交付，从交付提交提取声明的测试、替身、种子到两个独立历史检出。产品代码、依赖、编译产物各来自各自版本，测试材料逐文件限于项目明确的测试目录。可登记场景与检查点或定向测试名，要求稳定的目标断言及期望、实得。证明独立于合入、部署和评审，不改核心资格，不自行关闭问题单。

## 边界

改 src/**、test/**、README.md 与 docs/参考-运行细节.md。测试用隔离仓库、替身和临时目录，只有本次创建的检出可以清理。保存两版完整 SHA、材料摘要、命令、目标断言及原始日志，每次尝试可追查；已有完全相同的证明可引用。答复、提醒、真实模型和问题单维护由各自原入口负责。

## 验收标准

1. 在可复现问题的旧版运行与修复版相同的测试与种子，旧版命中登记断言呈现原问题且失败，修复版命中同一断言并成功。可从执行与批次结果追到两端 SHA、观察值、材料摘要和日志。
2. 定向单元测试用例也能给出同一目标断言的失败与通过；用例名称未选中、前置编译失败或其他断言先失败，都记未证明并写原始原因。
3. 两版都过或修复版也失败时，记录实得值和未证明原因；原合入资格保持原判。
4. 工作区已释放后凭登记执行仍能运行；选了测试目录之外的产品文件、路径逃逸或所需依赖不可得时，保留原因且原产品和用户工作区不变。
5. 重复或并发运行时，同一尝试只记一份检查和结果摘要，重试不覆盖旧尝试。未声明证明的卡继续原流程。
