# 参考：运行细节

[README](../README.md) 是命令和字段的入口；具体行为由 [11-24 调度定稿](需求-调度改为看账本补步骤.md) 定义。

## 账本、叫醒与恢复

每个执行的 `ledger.jsonl` 只追加。`开工` 持久化卡、固定配置、本人原话、授权步骤和批次依赖；`开始` 记录步骤、完整 SHA 和 PID 身份，工具结论按 `ref` 关联。同卡用内核文件锁（macOS `lockf`，Linux `flock`），进程退出自动释放，锁文件本身不删。`准备好` 记录用于创建工作区的 SHA 和复制文件摘要；这一 SHA 不等于后续检查的合并基点。每次检查、收货按提交与 dev 的合并基点现算。已由本执行合入的提交按合入前目标重算原检查绑定，不把合入自己误当成输入改变。

`tick` 按 ⓪–⑧ 决定下一步，不调模型、不等待检查完成。工具或 Pi 插件在记事实后叫醒，launchd 兜底。`查询` 返回原有 `loop-status/1`，额外的 `ledger` 给出规则命中、待本人说明、恢复汇总和每条「完成 / 合入」的 A/B 证据自检。新卡不读 `status.json` / `checks.jsonl` 推进；外部投影可以从账本重建。未留账本的历史执行仅用旧报告查询。切换前应停止或完成所有旧执行，回退切回原版本并移除新版定时项。

失败有原文，无失败态迁移。死工具的未竟开始算一次失败，按 `retry` 分档回补；`cardRetryBudget` 是整卡的累计自动重试上限。无法明确分类的交分诊，只接受收货、重跑、发回、等本人四类建议，不能代本人答复或放行。复测结果无法区分环境与产品时比较起点同命令；起点也失败按环境重试，不扣轮。首次超时重跑通过记「不稳」并带给评审，同测试第二次不稳按产品故障发回。合入冲突独立计数，不占检查轮或机械重试预算。

| 新等待 | 旧 `loop.wait` 投影 |
|---|---|
| 需求疑问、开发推不动 | 停下没交付 |
| 轮数用完 | 复测退回到上限 / 评审必修到上限（部署用收尾没走完） |
| 环境修不好 | 复测环境未就绪 / 收尾没走完 |
| 本人 Esc | `working / 开发中`，无 `wait`，不推飞书 |

`loop.facts.stops` 由等待和本人意图现算，`pendingReturn` 为尚未送达的待办，`reviewReturns` 为实际扣的评审轮数。命令回执、`checks.jsonl` 行仍给 PA 及 `tools/coordinate.ts` 读。没有 `已通知` 入口；PA 继续用旧通知接口。

## Pi 开发窗口

每卡一个可视窗口，工具须等插件登记实际进程。会话文件在执行目录 `sessions/`，断线重开传 `--session`；上下文超过配置比例、会话损坏、或 Pi 自动压缩后仍以超长结束时换新会话。开场文件从账本拼装提示词、验收、上一轮必修原文位置和收货 SHA；插件一起送最近收货后的全部待办。

`session_start` 报开；`agent_start` 报忙；`agent_settled` 报闲、最后助手文本、结束原因、错误和中止。`agent_end` 不是最终停下，不挂复测或评审。`input` 只记录登记的 Pi TUI 中交给 Pi 的交互原话（不记 UI 草稿、扩展注入或其他会话）；`窗口原话.jsonl` 保持旧导出格式。未关闭的疑问关闭，但评审只将这些原话当参考数据。正式答复则取 `答复` 意图。窗口闲时每秒查未送的待办，`sendMessage(triggerTurn)` 后记送达；重开新窗时重送最后一次收货之后的待办。

只有 `stop` 可进入忘交付判断。已经显式交付时，先等当前轮停下。`error` 走统一退避，其它非 `stop` 不收货、不扣轮；Esc 等本人，不重开。自行 `git commit` 仍不是收货。有改动先提醒一次（SHA 加改动指纹）；再次闲下，由分诊判断做完、疑问或继续。缺截图或 scope 越界均只发待办。Claude/Codex 启动和钩子停用；范围外的旧插件清单不会开启兼容调度。

### Pi 开发验证手册

在项目 `.pi/skills/verify/SKILL.md` 上提交普通文件（需 `name: verify` 与 `description`）。`bin/pi-dev` 临时加载该工作区内的文件，不开启技能自动发现、不跟随符号链接；可以用 `/skill:verify` 自查。`bin/pi-dev --dry-run` 只核对参数。验证手册不进入独立评审，也不替代卡上的测试命令。

## 复测与评审输入

两个检查在固定真实 SHA 的 detached worktree 中执行，前后核对 SHA 和跟踪文件；不读取开发窗口的未提交改动。检查的绑定包括 tree、合并基点、提示词与验收摘要、测试命令、场景、`localFiles` 字节摘要、配置、评审提示词和模型，以及草图和收货时保存的截图。检查过程中有新收货，旧结果照样记旧 SHA，不发回或扣轮。缓存只取适用的成功事实，不能用失败代替检查。

评审读完整要求、diff（返修同起点时以本轮修复 diff 为准）、单列删除文件和原行数、复测摘要、原稿证据、上轮必修、开发交付和回复、正式答复和窗口参考。`review-input-rN.md` 给历史工具读，同轮各尝试另存。若缺 `触发：` 等格式，交回评审员重排一次，不送新材料，不接受重排改变原文的结论或条数。无从确定原结论不放行。原稿和重排稿分存。

### 项目评审规则

「项目评审规则」读取合并基点的 `REVIEW.md` 和正文直接引用的仓库内相对文件。重复路径只读一次，不递归读，不跟绝对路径、网址、子模块或链接文件；缺文件可见，不用开发区后来加的规则填补。项目规则补充 R1 的通用必修门槛，不把只能看截图的条目报成静态必修。标「阻断：」的需求疑问等待答复。

### R1 历史评审回放

`node tools/replay-r1.ts` 是 R1 的独立静态重评，真实调用项目模型并写 `docs/评审/R1-回放.md`。N1 的历史比较是 `node test/replay-history.ts [任务目录]`，只读旧 `checks.jsonl`、旧报告中的等待事实。不重跑历史模型或项目，也不把缺本人原话的旧越过放行当作新版授权。

## E2E 项目报告

`tasks[].test` 接收 `LOOP_E2E_DIR`（未声明 E2E 时无此变量）。同一命令跑普通测试和 `plan.json` 列出的场景；计划含 `executionId / attempt / commit / promptHash / acceptanceHash / e2eHash` 及 `scenarios`。结果须原样回写前三个身份字段。`test.log`、`result.json` 和检查点证据独立归档。项目原子发布 `result.json`；用隔离的替身、数据和种子，不把凭证写到证据。

```json
{
  "executionId": "demo", "attempt": "本次编号", "commit": "完整 SHA", "unit": "通过",
  "scenarios": [{"id": "S4", "status": "通过", "steps": [
    {"id": "完成通知条数", "status": "通过", "actual": 1, "evidence": ["S4/通知.json"]}
  ]}]
}
```

- 状态用「通过 / 失败 / 未验证」，`actual` 是非空字符串、有限数值、布尔或 null；声明 `expected` 时按值精确比较，不转类型。每个选中场景恰一条；失败可跳过后续连续检查点，不允许跳过中间项。证据是本次目录内相对的普通文件，不是计划、报告和测试日志。
- 通过须命令退出 0、普通与报告检查全部通过。外部前置故障须在卡上声明 `dependencies`，探测要在进入产品前，检查点写 `status: "未验证"`、`cause: "外部环境"`、`dependency`、`actual`、`error`、`probe`，探测文件列在 `evidence`。探测须含同 `executionId / attempt / commit`、同依赖、`result: "不可用"` 与同一原错。
- 只有退出 75、完整外部探测且没有普通/产品失败才记环境没验证。退避重跑，累计耗尽等本人。新版不支持 `续跑 --接受环境缺项`；环境缺项不是复测通过。确需放行只用显式接受未验证。

## 防复发证明报告

`证明` 固定最近交付和开工声明。两端各自从本地对象检出到独立临时 Git 仓库和 HOME/TMPDIR，不带 `localFiles`、凭证、其他检出配置或共享依赖。清空登记的 `proofTestDirs`，仅挂载交付版 `testFiles` 的字节与执行位；不允许链接、子模块、越界或未登记的材料。两端各跑登记的 setup 与测试；这不是操作系统沙箱，只用于获准的本地脚本/替身。

- E2E 定向证明的计划只有一个场景检查点；普通检查填「通过」。旧版在指定断言处失败、退出 `1`；新版通过、退出 `0`。
- 单元用例用 `LOOP_PROOF_DIR` 的计划定位同一稳定 `testName`。原子发布 `result.json`，回写 `executionId / attempt / commit / testName / expected`，另有 `status` 与 `actual`。确认恰选中此用例且在指定断言取得旧实得后才退出 `76`，新版通过退出 0。未选中、编译、环境、其他断言不能当旧红。
- 执行目录 `proofs/<尝试>/` 留总计划、总结果、`before/` / `after/` 的命令输出及证据。复用须重新核对归档字段、声明、两端原始报告和文件摘要；异常留在 `ignoredAttempts`，不补写、不覆盖损坏记录。`checks.jsonl` 的「防复发证明」给复盘用，不影响放行。

## 合入、推送、部署、释放

- 合入、部署独立读取账本：最后收货提交必须有同输入的真实复测和评审均通过（A），或有绑定该提交和输入的本人「接受未验证」原话（B）。伪造 `完成` 无法放行。`--commit` 可用短 SHA，但须解析到最新收货。合入先试合，冲突只发回文件列表；实际合入生成双亲 merge，不覆盖 dev 的无关改动、不撤销手工合并。合入后重试只补缺的结论，不重复创建 merge。
- 推送只到 `origin/dev`，刷新 origin 远端分支、不推标签、不强推。扫描 dev 引入的提交新增行（私钥、常见 API 密钥、非模板 `.env`），只输出位置和规则，不回显内容。网络错重试、鉴权问题等待。显式 `合入 --推送` 或卡的推送授权才调用。
- 部署在独立检出，脚本是本仓库普通可执行文件，固定使用开工的 `deploy` 配置。环境含 `LOOP_DEPLOY_COMMIT`、`LOOP_REPO`、`LOOP_EVIDENCE_DIR`；失败回退另有 `LOOP_DEPLOY_FAILED`。`cmd`、`check`、`rollback` 输出和部署前后快照保留，回退也失败立即等本人。已开始且异常中断的部署先补偿回退，不能当成功直接重试。人工退回只允许项目最新记录的成功部署、需要登记回退脚本，不改 dev。脚本须负责线上迁移、幂等和安全回退，不能靠旧备份覆盖用户可变数据。
- 卡上已授权的收尾成功后释放。检查工作区有无改动；Git 工作区移动、替换或有未提交内容均不删除。已释放仍保留 Git 分支、证据和报告。放弃明确授权后移除工作区，分支和证据仍保留。
- `snapshot` 可选，`scenario` 为独立替身场景、`live` 为线上只读检查。脚本把 JSON 对象写到 `LOOP_SNAPSHOT_OUT`，读取 `LOOP_SNAPSHOT_MODE`；`TMPDIR` 独立。无脚本跳过，留痕失败不作结论。`对比` 只报新增、减少、变化。已接入 E2E 的复测不重复采 scenario。

## 协调工具的输入和存档

`tools/coordinate.ts` 保持原入口，按 `task.json.repo` 隔离项目，状态优先走公开 `查询`，并从 `checks.jsonl`、结果原文、快照、正式答复和窗口原话分析信号。可选 `.dev-loop-coord.json` 指定 `issues`、`batches`、`featureList`、`featureMap`、`verifySkill`、`seeds`、`deferred`、`acceptanceReaderReady` 和 `reviewAudit`；路径相对项目根。只查不写，应用须本人已授权并再次传原 `planId`，锁内重算，保留原件并报告冲突。月报、档案计划和回执在项目 `.dev-loop-coord/`，可含私有内容，不提交、不发给别的项目。

关单须实际同版双通过及登记的回归证据（除非明确「拦不住」），授权与业务验收单独核验。未确认不等于通过；批次反馈不能替代单独授权。首次开工的 `previous`、`candidates`、`blocked`、`health` 可照旧查看，不代投递、部署或修改 PA。
